## Changes and fixes

- Manager History defaults to **Receipt history**, grouped by persisted approved draft ID with all included Intake lines, document date, official names and quantities. Details retain raw/reviewed values, units, MYT approval time and Manager account. Same-date receipts remain separate. **Stock activity** separately searches/filters Take/Return and explicitly labelled Manager opening balances. History remains Manager-only; this presentation change performs no ledger writes.
- Excluded blank/unreadable lines accept an empty reviewed description plus a required reason. Raw extraction remains intact. Included lines still require valid product, positive integer base-unit quantity and approval fields. No schema migration is required.
- Saved drafts offer a temporary comparison image with change/remove controls and comparison-specific accessible text. This never posts createDraft, calls Gemini or changes stock. No original image is recovered or permanently retained.
- Extraction has a **45-second server deadline**, an AbortSignal, supported SDK HTTP timeout and **one attempt including the initial request**. Timeout returns 504 with deliberate-retry guidance; provider failure returns 502. Neither saves a draft nor changes stock. There is no automatic scan retry or automatic camera capture.
- Fixed the new-demo semantic/ARIA/focus/effect diagnostics and formatting. Inventory uses a native list, generic spans no longer carry unsupported labels, and aborted/outdated search responses are ignored.
- Browser verification found and fixed **cached Manager History after Staff movements**: History refreshes on entry; Inventory also refreshes on re-entry. It also reproduced **320px overflow from a 120-character unbroken product name**: text now wraps without hiding overflow.
- Added retained PostgreSQL/API and browser tests. `playwright-core` 1.64.1 is a development-only driver using installed Chrome; no browser binary was downloaded. Handoff/status, engineering contracts and tools/licence notes were reconciled; no unrelated product features were added.

## What was actually exercised

Browser automation used **real installed Chrome in headless mode**, fresh contexts, desktop 1280×900 and resized 390×844/320×844 viewports. I exercised Manager and Staff login, products/search/edit, Take/Return and stale-stock rejection, synthetic draft creation, saved-draft reload/comparison, corrections including date, manual conversion, unknown-product Opening 0, blank exclusion, actual-receipt confirmation, approval/discard, both History sections, filters, error/loading states, keyboard controls and long-name layout. Screenshots were also inspected. A desktop computer-use connection timed out at app approval; it was not used to access operational records. The separate automated browser provided the actual interaction evidence.

Backend tests used a **fresh uniquely named schema** per run, verified `current_schema()` before application code, and used actual PostgreSQL transactions and actual API handler/auth code. The provider module was replaced only inside the test process. Browser tests separately ran a temporary copy of the current source against another owned schema and a **loopback HTTP provider stub through the real SDK**. A preview identity check prevents targeting another service. External fetches are blocked; the normal app has no test/mock fallback. Synthetic PNG content is authored by the test. A 500ms stub delay makes loading-state checks observable; it is not a latency measurement.

Both fixtures removed only their own schemas. The browser fixture stopped only its own child server tree, verified its temporary absolute directory and removed that copy. No operational rows were read as test data, reset, seeded, edited or deleted. Existing local credentials/session secret and unrelated working-tree changes were preserved. The Git index was unchanged; no commit, push or deployment.
