### Isolated PostgreSQL harness details

A fresh random `estock_audit_…` schema was created solely for synthetic checks. Synthetic image bytes tested upload validation, not real image decoding or OCR accuracy.

Assertions covered:

1. Empty inventory; product creation/Opening exactly once on replay; changed-input conflict; invalid Opening rejection.
2. Low-stock boundary at 0/4/5/6 and case-insensitive search.
3. Confirmed exact alias, alias collision and partial-name non-assignment.
4. Unknown product created with Opening 0; manual 2 boxes to 24 pcs; raw/final preservation; actual-receipt confirmation required.
5. Multi-line Intake to the same product, old document date, terminal immutability, repeat approval rejection and persistent replay.
6. A test-only trigger fails the second Intake insert: all stock, movements, request identity and status roll back; removing it allows the same request to commit once.
7. Concurrent Takes of 4 against stock 5: exactly one succeeds, balance 1; Return replay has one effect; invalid quantities and changed-input key reuse reject.
8. Concurrent approvals have one effect; stale draft revision and product rename conflict; resave permits a current selection. A simultaneous save/approve race allows one operation, with stock matching the resulting status.
9. Corrected draft re-read preserves raw values; discard persists and changes no stock.
10. Stubbed provider failure/invalid JSON and invalid/oversized uploads do not change stock.
11. Confirmed defect: excluding a blank unreadable line with a reason is still rejected for blank reviewed description.
12. Separate Manager/Staff sessions with authorised shared development configuration; Staff denied all nine Manager handler operations; production rejects shared-password configuration.
13. Localhost Origin with bind-address URL accepted; changed port/origin, cross-site metadata and forwarded-host spoof rejected.

Final SQL reconciliation confirmed every synthetic product's stock equals the sum of its movement deltas. All pooled connections closed and the uniquely owned test schema was removed; catalog query confirmed cleanup. The test trigger/function existed only in that schema. Temporary harness/log names: `audit-runtime.mjs` and `estock-audit-runtime.log` under the session's OS temp directory. Invocation used `node --experimental-transform-types <temporary-harness>`; plain strip-only mode initially rejected the existing TypeScript parameter-property syntax, so that harness setup was corrected before the successful run. No application change was needed for it. The harness and logs are not shipped as durable tests; repeatable checked-in coverage is a remaining action.
